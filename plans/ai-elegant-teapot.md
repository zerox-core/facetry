# 登录页方案：「可以动手的简历桌面」

## Context
演示和登录卡总是在抢位置。你的判断是：把演示做成可交互的，它就不再是一个要占地方的「展示盒子」，而是页面本身的一部分。代价是周围会空，需要装饰来填。方案是把整页做成一张面试官的桌面：中央是一份可以动手操作的简历，四周散放真实产品里的碎片当装饰，登录卡放在桌面右侧。

## 交互（简历纸，复用 `LoginShowcase` 的数据和计时）
- **默认自动播放**：导入扫描 → 自动标注 → 生成追问 → 现场记录，每步 2.4 秒。简历下方的四个进度点可以点击跳步。
- **动手模式**：用户一碰简历（hover 或点击），自动播放就停下，改由用户操作：
  - 悬停某一行，这行会被高亮，页边出现对应的标签（亮点或待核实）；
  - 点击「待核实」标签，从这一行拉出一条 SVG 连线，末端生成一张追问便签；
  - 点击便签上的要点，可以勾选，便签底部 1–5 分可以打分。
- **重置**：在简历右上角放「重新演示」，简历页脚放一行提示「试试：点击标黄的一行」。
- 所有交互只停留在页面里，不影响登录状态，也不写入 localStorage。

## 装饰（全部取自产品本身，不用抽象图形）
- **今日面试便签**（左上）：一张略微倾斜（-2°）的白色小卡，写着今天的日程：刘一帆·算法 14:00、何思雨·Java后端 16:30。
- **题库卡片**（左下）：一张题卡「事件循环中微任务的执行时机？」，带难度点，倾斜 1.5°。
- **两份叠放的简历**：主简历纸后面错位露出两张纸的边角（`translate` 加阴影），暗示「还有一叠待读」。
- **细节**：一枚墨蓝回形针（SVG）夹在主简历纸顶部；桌面四角淡淡的尺规刻度线（slate-300/40%）。
- **视差**：鼠标移动时装饰卡片轻微跟随（位移不超过 6px，transform），开启 `prefers-reduced-motion` 时关闭。
- 装饰全部设为 `pointer-events-none aria-hidden`，低对比度（opacity 70–85%），不能盖过简历和登录卡。
- 禁止：渐变光效、玻璃拟态、全大写、衬线字体、emoji。

## 登录卡
- 放在简历纸右侧，与纸张顶部对齐，宽 360px，白底，`ring-1 ring-slate-200`，顶部一条 2px 墨蓝细线。
- 追问便签从简历纸的页边伸出来，落在登录卡上方的空隙里，把两者在视觉上连起来。
- 内部的飞书扫码、账号密码表单和状态逻辑原样不动。

## 响应式
- ≥xl：完整桌面加全部装饰。
- lg：去掉左侧装饰卡片，简历缩到 600px。
- <lg：只保留登录卡居中，下方放一行「在电脑上打开可体验简历分析演示」。

## 修改文件
- `src/views/LoginShowcase.tsx`：重构为「简历纸」组件，状态为 auto 或 manual（manual 下记录 hover 行、已生成的追问、勾选项、评分），保留 STEPS / DUR / LINES / TONE。
- `src/views/LoginDesk.tsx`（新增）：桌面装饰，包括今日面试便签、题卡、叠纸、回形针、刻度线和视差。
- `src/views/Login.tsx`：外层改为桌面网格（装饰 / 简历 / 登录卡），登录卡逻辑不动。
- `src/index.css`：新增 `.login-desk` 点阵背景和 `login-draw` 连线动画，复用已有的 login-* 动画。

## 验证
在 1440×900、1280、1024、390 下预览，检查以下几点：
- 自动播放和动手模式能正常切换，重新演示能复原；
- 连线准确指向便签，装饰不遮挡、不可点击；
- 开启减少动态效果时视差关闭；
- 两种登录方式都能进入工作台。
