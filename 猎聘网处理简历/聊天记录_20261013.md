### 5. 修复"只判定不点击"的 BUG
**用户**:出问题了,AI 判断不合适/合适后,没有在页面中点击按钮,15 份还是未处理,修复这个 BUG。

**根因定位**:
- **表面**:`config.json` 里 `dry_run: true`(仅模拟)→ 只定位按钮、从不真点。
- **两个真 BUG**:
  1. `liepin.py` 的 `find_button_rect` 里 `scrollIntoView` 后**立刻**读 `getBoundingClientRect()`,若页面用 `scroll-behavior: smooth`,读到滚动**前**的旧坐标 → 鼠标点错位置 → "点了但没反应",且成功时静默,完全看不出来。
  2. `mark_operated` 定义了却**从未调用** → 就算真点成功,数据库 `operated` 也永远是 0,无法验证。

**修复**:
- `config.json` 改 `dry_run: false`(真实点击)。
- `liepin.py` 强制 `behavior:'instant'` 瞬间滚动 + 等 0.35s 二次定位 + 点击前校验坐标必须在视口内,否则**明确报错**而非悄悄点空。
- `scanner.py` 真实点击成功后调用 `mark_operated` 落库标记。
- 加防复发告警:开着仅模拟扫描时,日志直接弹**黄色警告**「⚠️ 不会点任何按钮,简历仍是未处理」。

### 6. 是否开着仅模拟的澄清
**用户**:我刚刚没有开着仅模拟吧。

**处理**:更正了此前"operated=0 即铁证没点"的过度解读——因为 `mark_operated` 当时没记录,`operated=0` 不能证明"没点"。剩两种可能:A 仅模拟当时确实开着(页面加载时勾选框会自动勾上,易忽略);B 关了但点击失败且静默(最可能就是坐标 BUG)。建议看面板提示文字回想:显示「⚠️ 仅模拟…」= A;显示「🔴 真实操作…」= B。

### 7. 先不换兜底,用户自测
**用户**:先不要(换成 JS 合成点击兜底),我现在再试一下。

**处理**:给出验证要点——必须先重启后端(配置启动时只读一次)、调试 Chrome 窗口放前台别最小化、小批量(2~3 份)试跑,重点看:开头不该再有"仅模拟"黄字、每份应是"已点合适/不合适"而非"暂不点击"、有无黄色告警、猎聘页面简历是否真的消失、数据库 `operated` 是否变 1。

### 8. 扫描速度太慢,要求提速
**用户**:猎聘网扫描都正常使用了,但速度实在太慢,有时候 3-6 分钟才一份,间隔时间太长,适当缩短。

**实测**(避免猜):每份平均 **247 秒**;AI 评估仅 8~10 秒(非瓶颈);CDP 通信 evaluate 1ms / 鼠标事件 17ms(非瓶颈);三次会话 41s/93s/273s 每份,波动极大说明有不稳定环节。

**处理**:
- 加 `⏱ 耗时统计` 埋点(扫描结束只多一行,不污染每份日志):`⏱ 耗时统计:15 份,平均 X 秒/份 → 打开页面 A s · AI评估 B s · 点击 C s · 间隔等待 D s`。
- 缩短间隔:份间 4.5-9s → **2.5-5s**;微休 每5份 25-70s → **每8份 15-35s**;长思考 12%(8-20s) → **8%(5-12s)**;阅读停留 1.2-3.5s → **1-2.5s**(平均约省 10 秒/份)。
- **保持不变**的是真正防风控的三项:`humanize`、`real_mouse` 真实鼠标、单批上限——防识别靠拟人行为而非长间隔。

### 9. 上限 15 → 20
**用户**:这个速度还可以,把猎聘网扫描上限由 15 份改成 20 份。

**处理**:`config.json` 的 `scanner.liepin.max_per_session` 15 → 20。`scanner.py` 是动态读取该值(无硬编码 15),改配置重启即生效。单批 20 份时微休在第 8、16 份各触发一次。

### 10. CRA 硬规则强制
**用户**:最近经常把没有 CRA 工作经验的人选判断为合适,加一个要求:没有 CRA 岗位工作经验的,即使其它条件符合,也判断不合适。

**根因**:实际运行走 LLM 评估(`llm.enabled=true`),而 `match()` 入口在 LLM 开启时**根本没调用规则版的硬淘汰**,模型只是把备注当提示塞进 prompt,遇到"其它条件都符合"常判合适。

**处理**:`app/core/jd_matcher.py` 新增 `apply_post_hard_rules()`,在 `match()` 末尾**统一强制兜底**——凡是 JD 备注声明"没有X经验不考虑"且简历正文无该项,就**强制"不合适"**(覆盖 LLM 结论,reason 加 `[硬规则强制]` 前缀)。改进了提取正则,支持"没有A、B、C的都不考虑"并列结构(避免误伤 SSU 岗:有 CRC 经验不应被淘汰)。已用 5 个场景测试全对(有 CRA→合适;无 CRA 药品注册→不合适;SSU 有 CRC→合适;SSU 无任何相关→不合适)。**对所有带"没有X经验不考虑"备注的 JD 都生效**(CRA / SSU / 财务总监等)。

### 11. 两平台能否同时扫描
**用户**:猎聘网和前程无忧扫描可以同时使用吗?

**答**:**不能**。
- 后端硬锁:`app/main.py` 的 `api_scan_start` 第一句 `if SCANNER.is_running(): return 400 "已有扫描在运行"`;`scanner.start()` 也有同样判断。Scanner 是全局单例(单线程 `_thread` + 单份 `_state`),无法并发。
- 即使绕过锁也会乱:两平台共用**同一个调试 Chrome**(CDP 9222),扫描会切换标签页、打开详情、点按钮,并发会抢页面、串按钮。
- **必须顺序跑**:先扫一家、停/跑完,再扫另一家。两家数据按 `platform` 字段合并在同一看板,查看不受影响。

## 三、当前关键配置速查(接手必读)

- **后端**:Flask,入口 `app/main.py`,端口 **7788**
- **浏览器**:调试 Chrome,CDP 端口 **9222**(启动参数 `--remote-debugging-port=9222 --remote-allow-origins=*`)
- **`config.json` 生效项**:
  - `scanner.auto_operate`:自动操作总开关
  - `scanner.dry_run`:**必须 `false` 才真实点击**(`true` = 仅模拟,只判定不点,简历仍"未处理")
  - `scanner.liepin`(仅作用于猎聘):
    - `humanize: true`、`click_mode: "real_mouse"`(真实鼠标,替代 `el.click`)
    - 份间抖动 `min/max_delay_ms: 2500 / 5000`
    - 阅读停留 `reading_min/ max_ms: 1000 / 2500`
    - 微休 `micro_break_every: 8` 份,`micro_break_min/max_ms: 15000 / 35000`
    - 长思考 `thinking_chance: 0.08`,`thinking_min/max_ms: 5000 / 12000`
    - `mouse_jitter_px: 5`
    - `max_per_session: 20`(单批上限)
    - `eval_max_wait_sec: 90`
- **数据**:`data/recruit.db`(SQLite,主表 `candidates` / `scan_sessions`)
- **JD 来源**:`职位JD汇总.xlsx`(在"备注"列写"没有X经验的不考虑"即自动生效硬规则,无需改代码)
- **改配置必须重启后端才生效**(Scanner 启动时 `load_config()` 只读一次)

## 四、已知坑(务必看,避免重蹈)

1. **「仅模拟」(dry_run)是头号坑**:开着只定位不真点,简历扫完仍是未处理且日志静默。现已加黄色告警防复发。

5. **LLM 路径下硬规则靠 `apply_post_hard_rules` 强制兜底**,否则模型会无视备注判合适(CRA / SSU / 财务总监等岗都依赖它)。
