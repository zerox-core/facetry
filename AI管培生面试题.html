AI 管培生面试题方案

岗位定位：Agent 用得好（核心）· 有 AI 基础 · 具备思维能力与审美

快问快答 60 min（基础+进阶+深度学习+后端）面谈 40 min 题目来源：知乎 Agent 面试题汇总 + 深度学习八股文总结

设计思路

  • 进阶题权重最大（30%）：Agent 要用得好，先要理解得深——进阶快答考工作模式、记忆、安全、成本等工程落地认知，区分"用过"和"用明白"。
  • 基础题只考"知道"：不背八股，每题 3-5 句话能讲清即可，用来快速筛掉完全没接触过的人。
  • 深度学习与后端各 10%：管培生不需要会训练模型或独立运维，但要听得懂技术团队在说什么——梯度爆炸、索引、Docker 这些词不能一脸茫然。
  • 思维题考结构化与取舍：答案无标准对错，看论证质量与判断力。
  • 审美考"能指出具体问题"：只会说"感觉不好看"的不得分，能讲配色、层级、留白、文案腔调的才是真审美。

A1Workflow 和 Agent 有什么区别？什么场景下你会选 Workflow？

考察点：控制权在代码手里还是 LLM 手里。加分项——提到"生产上常见 Workflow + Agent 混合架构"。
查看参考答案
核心区别：Workflow 的控制权在代码手里——流程是人预先定义的固定步骤，LLM 只在某些节点被调用；Agent 的控制权在 LLM 手里——由模型自主决定下一步做什么、调什么工具、何时结束。
量化对比：Workflow 可预测、易调试、Token 消耗低（约 1x）；Agent 灵活、能处理开放式任务，但 Token 消耗约为其 4-8 倍、调试难度大。
场景选择：流程固定、规则明确的任务（报销审批、定时报表）选 Workflow；开放式、路径未知的任务（深度调研、复杂排障）选 Agent；生产环境最常见的是混合架构——Workflow 提供稳定骨架，Agent 处理异常和复杂分支。

A2LLM 和 Agent 有什么区别？

查看参考答案
LLM 本质：基于条件概率的文本生成模型（预测下一个 token），是无状态函数。
LLM 四大天花板：只会说不会做、没有记忆、知识有截止日期、不会规划。
Agent = LLM + 工具 + 记忆 + 规划。四大模块：LLM（大脑）、规划模块（任务拆解）、记忆模块（短期上下文 + 长期外部存储）、工具模块（Function Call / MCP 等）。一句话：LLM 是引擎，Agent 是装了引擎、方向盘和轮子的车。

A3如果 Agent 陷入死循环，你会怎么办？

查看参考答案
三层防护：① 最大步数限制（如 20 步强制停止）；② 重复动作检测（连续相同 action + 相同参数则中断）；③ 超时控制。
加分项：提到事后排查——通过执行日志/轨迹定位循环根因，常见原因是工具返回格式不符合预期、目标定义模糊、或工具结果没有信息量导致模型反复重试。

A4Function Call 是什么？用一句话说清楚。

查看参考答案
一句话：LLM 按预先定义的函数 schema 生成结构化调用指令（函数名 + JSON 参数），由外部代码真正执行，结果再传回 LLM 继续生成。
关键认知：LLM 自己并不执行函数，执行权在外部宿主代码——Function Call 解决的是"什么时候调用、传什么参数"这两个问题，是 Agent 调用工具的基石。四步流程：定义工具 → LLM 生成调用指令 → 代码解析执行 → 结果传回。

A5MCP 是什么？它解决了什么问题？

查看参考答案
定义：Model Context Protocol，Anthropic 推出的开放协议，统一 Agent 与外部工具/数据源的接入标准。
解决的问题：N×M 爆炸——N 个应用接 M 个工具，原本要写 N×M 个定制适配；MCP 统一协议后只需 N+M 个实现，工具还能被动态发现。
架构：三角色（Host / Client / Server），提供三类能力（Tools / Resources / Prompts），底层基于 JSON-RPC 2.0，传输支持 stdio（本地）和 HTTP+SSE（远程）。

A6RAG 和 Agent 是什么关系？

查看参考答案
目的不同：RAG 是"补充知识"——检索相关文档塞进上下文再生成，流程固定；Agent 是"完成任务"——动态规划、调用工具、多步执行。
核心观点：两者不是对立关系，RAG 是 Agent 工具箱里的"知识查询器"，是 Agent 可调用的工具之一。
进阶：Agentic RAG——由 Agent 自主判断何时检索、检索什么、是否需要换角度多查几轮。

A7写 Prompt 时，你觉得最重要的三件事是什么？

查看参考答案
开放题，看真实使用习惯。好答案通常覆盖：
① 明确角色与目标——你是谁、要完成什么、验收标准是什么；
② 给出输出格式与示例——结构约束、few-shot 示例，让输出可直接使用；
③ 约束边界——不许做什么、数据不确定时怎么办、什么情况下要反问。
加分项：提到上下文给足背景、复杂任务先拆解、Prompt 需要迭代打磨而不是一次写好。

A8你平时用哪些 AI 工具？各自用来干什么？

查看参考答案
开放题，无标准答案，但信息量最大。
好答案特征：能区分工具特性并讲出具体场景，例如"写代码用 Claude/Cursor 因为上下文长、改工程文件稳""查资料用 Perplexity/豆包因为带搜索引用""生图用即梦/Midjourney"等；能说出某个工具的具体坑和规避方法。
扣分信号：只会说"ChatGPT 什么都干"、说不出任何工具间的差异、列举的工具全是道听途说没有使用细节。

B1Agent 有哪些工作模式？说说 ReAct 是怎么工作的。

查看参考答案
四种模式：① ReAct——Thought → Action → Observation 循环，边想边做，最常用；② Plan-and-Execute——先完整规划再逐步执行，路径稳定但难应对中途变化；③ Reflection——执行后自我反思、修正输出；④ Multi-Agent——多个智能体分工协作。
ReAct 优缺点：决策过程可见、易调试；缺点是步数多、Token 消耗高，可能陷入循环（呼应 A3）。

B2Agent 的记忆系统怎么设计？RAG 算记忆的一部分吗？

查看参考答案
两层记忆：短期记忆 = 上下文窗口；长期记忆 = 外部存储（向量数据库、关系数据库、KV 存储）。
记忆放不下的三种压缩策略：滑动窗口（只留最近）、摘要压缩（旧对话浓缩成摘要）、重要性过滤（只保留关键信息）。
与 RAG 的关系：算——向量数据库就是外部记忆的一种，通过 RAG 式语义检索召回长期记忆。加分项——提到记忆的读写时机（什么时候写入、什么时候召回）也是设计难点。

B3Function Call 和"Prompt + 正则解析"有什么区别？

查看参考答案
Prompt + 正则：让模型自由输出文本，再用正则提取参数——格式脆弱，模型稍微变个说法就解析失败。
Function Call：模型训练时对结构化输出做过对齐，按预定义 schema 生成函数名 + JSON 参数，成功率高、可校验、还支持并行调用（Parallel Function Call）。
一句话：正则解析是"赌模型按格式说话"，Function Call 是"协议保证模型按格式说话"。

B4要给团队接入 10 个外部工具，用 MCP 还是直接写 Function Call？为什么？

查看参考答案
看取舍，不看出身：工具数量多、要跨团队/跨应用复用、需要动态发现新工具 → MCP（标准化接入，避免 N×M）；只有一两个内部工具、追求简单直接 → Function Call 就够，不必为上协议而上协议。
本质区别：Function Call 是模型层面的"打电话"能力；MCP 是统一的"通讯录和电话系统"——前者解决单次调用，后者解决规模化接入。
加分项——能指出 MCP 的成本：多一层协议 = 多一份部署维护成本和调试复杂度。

B5Skills 和 System Prompt、Few-shot 有什么区别？

查看参考答案
Skills：把领域专家经验编码成文件（身份定位 + 工作流程 + 注意事项 + 输出规范），按需激活、可维护可复用。
System Prompt：全局常驻的系统级指令，每次对话都占用上下文。
一句话区分：Few-shot 教格式，Skills 教方法论。
加分项——提到激活机制（按关键词/语义相似度触发，不占常驻上下文）。

B6Agent 要操作数据库，怎么保证它不会误删数据？

查看参考答案
四道防线：① 最小权限原则——只给只读账号或限定表的权限；② 危险操作 Human in the Loop——删改前必须人工审批；③ 幂等性 + 回滚机制——操作可重试、可撤销；④ 降级策略——异常时退回安全状态。
加分项——提到 Prompt Injection 威胁：恶意输入可能诱导 Agent 执行危险操作，需要对工具返回内容做隔离和过滤。

B7Agent 的 Token 消耗很大，怎么优化成本？

查看参考答案
五个策略：① 工具选择优化——减少无效/冗余的工具调用；② 模式选择——能用 Workflow 就不用 Agent（可省约 4 倍 Token）；③ 上下文压缩——摘要、滑动窗口控制长度；④ 模型路由——简单步骤用小模型，复杂推理用 flagship；⑤ 缓存——相同查询/工具结果直接复用。
加分项——提到先度量再优化：按任务类型统计 Token 分布，抓大头。

B8生产环境的 Agent 常见的坑有哪些？

查看参考答案
五大坑：① 死循环（对应 A3）；② 幻觉工具调用——调用不存在的工具或编造参数；③ 上下文污染——错误信息进入上下文后被不断放大；④ Token 爆炸——长任务成本失控；⑤ Prompt Injection——用户输入或外部内容注入恶意指令。
考察意图：能答出 3 个以上说明关注过工程落地；只答"模型幻觉"一个的，理解还停留在表面。

E1梯度消失和梯度爆炸分别是怎么回事？怎么解决？

查看参考答案
成因：深层网络反向传播时梯度是连乘形式——层间梯度小于 1 反复相乘 → 指数级变小（消失），靠近输入层的参数几乎不更新，深层网络退化等价于浅层；梯度大于 1 反复相乘 → 指数级增长（爆炸），权重更新过大，loss 变 NaN。常见于深层网络/RNN、权重初始化过大、用 sigmoid 这类导数很小的激活函数。
解决：梯度裁剪（设阈值）、权重正则化、Batch/Layer Normalization、残差连接（ResNet 的 shortcut）、合适的初始化（Xavier/He）、换 ReLU 系激活函数。

E2常见优化器有哪些？SGD 和 Adam 有什么区别？

查看参考答案
SGD：每个 batch 算梯度就更新，简单快，但更新方向完全依赖当前 batch 的梯度，震荡大、不稳定。SGD + 动量（Momentum）：累积历史梯度方向，像带惯性的小球，减少震荡、加速收敛。
Adam：= 动量（梯度一阶矩）+ RMSprop（二阶矩自适应学习率）+ 偏置修正，为每个参数动态调整学习率，收敛快且平稳，是大多数场景的默认选择。
核心区别：SGD 所有参数共享一个学习率、只看当前梯度；Adam 利用历史梯度信息、逐参数自适应。加分项——知道 Adam 可能过拟合前期特征，某些任务上 SGD+动量泛化反而更好。

E3过拟合是什么？怎么判断、怎么解决？

查看参考答案
定义：模型在训练集上表现很好，但在测试集/新数据上很差（高方差）；对照欠拟合——训练测试都差（高偏差，模型根本没学会）。
原因：模型太复杂参数太多、训练数据太少、训练/测试分布不一致、噪声被模型记住了。
解决：降低模型复杂度、数据增强、正则化（L1 惩罚权重绝对值→稀疏可解释；L2 惩罚权重平方和）、Dropout、早停（early stopping）、加更多数据。

E4Transformer 的自注意力机制是什么？Q、K、V 分别干嘛的？

查看参考答案
Self-Attention：让序列中每个位置都能"看到"并加权聚合其他所有位置的信息，一步到位建模全局依赖（对比 RNN 的逐字串行）。
三个向量：每个 token 生成 Query（我要找什么）、Key（我有什么特征可被检索）、Value（我实际携带的信息）。用 Q 和所有 K 算相似度（点积 → 缩放 → softmax 得权重），再对 V 加权求和得输出。
多头注意力：多组 QKV 并行计算，从不同子空间捕捉不同关系。加分项——提到为什么要除以 √d 缩放（防止点积过大导致 softmax 梯度消失）。

E5Transformer 为什么用 LayerNorm 而不用 BatchNorm？

查看参考答案
BN：按 batch 维度统计均值方差，要求 batch 内样本独立同分布——CV 中图像之间独立，适合 BN；NLP 中同一 batch 句子长短不一、token 间有强关联，batch 统计量不稳定且语义上不合理。
LN：在单个样本内部做归一化，与 batch size 无关，训练和推理行为一致，更适合序列建模。
一句话：BN 是"跨样本"归一化，LN 是"样本内部"归一化，NLP 数据特性决定了只能用后者。

E6BERT 和 Transformer 是什么关系？

查看参考答案
关系一句话：Transformer 是架构，BERT 是用这个架构的 Encoder 一半堆叠起来、加预训练任务训练出来的模型——不是新架构。
两个预训练任务：MLM（掩码语言模型——随机遮住约 15% 的 token 让模型根据上下文预测，实现双向理解）和 NSP（判断两句话是否相邻）。
对照：GPT 用的是 Transformer 的 Decoder 一半（单向/自回归），适合生成；BERT 双向注意力，适合理解类任务（分类、NER、问答）。

E7神经网络参数为什么不能全部初始化为 0 或同一个常数？

查看参考答案
同一层所有神经元初始值相同 → 前向输出相同、反向梯度也相同 → 永远更新成一样的值，所有神经元在计算同一个特征，网络退化成只有一个节点，丧失学习能力（对称性无法打破）。
所以要随机初始化，且 Xavier/He 初始化还会按层缩放方差，让各层输入输出数值范围稳定。注意：逻辑回归（无隐藏层）初始化为 0 是可以的。

E8训练时 loss 突然变成 NaN，可能是什么原因？怎么排查？

查看参考答案
最常见：梯度爆炸——学习率过大、权重初始化不当、缺少归一化，权重更新过大溢出，loss 变 NaN。
也可能是：脏数据（输入里有 NaN/Inf）、数值计算问题（log(0)、除零）、混合精度溢出。
排查顺序：先降学习率试试 → 加梯度裁剪 → 检查数据是否有异常值 → 检查初始化 → 加 BN/LN。

F1Linux 上一个服务挂了，你怎么排查？（考常用命令）

查看参考答案
看进程：ps aux | grep xxx / systemctl status；看端口：ss -tlnp 或 netstat -tlnp；看日志：tail -f app.log / journalctl -u 服务名、grep ERROR app.log；看资源：top（CPU）、free -h（内存）、df -h（磁盘）。
考察意图：能随口说出 3-4 个命令并讲清排查顺序即可，说明真的碰过服务器。

F2Docker 是什么？和虚拟机有什么区别？

查看参考答案
Docker：容器技术——把应用和它依赖的环境打包成镜像，在任何机器上跑出一致的结果（"一次构建，到处运行"）。
与虚拟机的区别：虚拟机虚拟整个操作系统（每个 VM 有独立内核，重、启动分钟级）；容器共享宿主机内核，只是进程级隔离（namespace + cgroup），轻量、秒级启动、单机可跑更多实例。
好处：环境一致（开发=生产）、隔离、快速部署和扩容。

F3说几个你常用的 Docker 命令。docker-compose 是干嘛的？

查看参考答案
docker build -t 名 . 构建镜像；docker run -d -p 8080:80 名 后台运行 + 端口映射；docker ps 看运行中的容器；docker logs -f 容器 看日志；docker exec -it 容器 bash 进容器；docker stop / rm 停删。
docker-compose：用一份 YAML 定义多容器应用（如 web + MySQL + Redis），一条 docker compose up 全部拉起，自动管理容器间网络和启动顺序。

F4MySQL 索引是什么？为什么能加速查询？

查看参考答案
本质：帮助快速定位数据的数据结构，InnoDB 默认用 B+ 树。没索引 = 全表扫描 O(n)；有索引 = 沿树查找 O(log n)——B+ 树矮胖，3 层就能装千万级数据，叶子节点有序且链表相连，适合范围查询。
要点：最左前缀原则（联合索引 (a,b,c)，查询必须带上 a 才用得上）；索引不是越多越好——占空间、拖慢写入。
加分项——提到覆盖索引（索引里就有要查的字段，不用回表）。

F5一条 SQL 查询很慢，你怎么排查？

查看参考答案
步骤：① 开慢查询日志定位慢 SQL；② EXPLAIN 看执行计划——有没有走索引（key 列）、扫了多少行（rows）、是不是全表扫描（type=ALL）；③ 常见原因：没建索引，或索引失效（对索引列用了函数、隐式类型转换、LIKE 以 % 开头、违反最左前缀）；④ 数据量大时考虑分页优化（深分页 offset 问题）、读写分离、分库分表。
考察意图：能说出"EXPLAIN"这个词就及格，能讲索引失效场景就优秀。

F6MySQL 和 PostgreSQL 有什么区别？怎么选？

查看参考答案
MySQL：简单快、生态最大、读多写少的互联网应用标配。
PostgreSQL：功能强——JSONB、GIS 地理信息、窗口函数、CTE 都支持，SQL 标准兼容更好，事务和并发控制（MVCC）更严谨，复杂查询和数据分析场景更强。
选型：常规 CRUD 应用 MySQL；需要复杂查询/地理信息/JSON 文档/高一致性 PG。考察意图：不要求很细，看是否知道两者定位差异，而不是"都一样"。

F7有了 MySQL 为什么还要 Elasticsearch？

查看参考答案
MySQL：关系型数据库，擅长结构化数据的精确匹配和事务；但全文搜索弱——LIKE '%xx%' 不走索引、没有相关性排序、分词能力基本没有。
ES：基于倒排索引——分词后建索引，搜索直接定位文档，支持相关性打分（BM25）、模糊匹配、聚合分析、分布式水平扩展。
典型搭配：MySQL 存主数据（保事务和一致性），ES 做搜索（商品搜索、日志检索），通过 binlog/消息队列同步；再加 Redis 做缓存。加分项——能讲清这套分工。

F8把一个 Web 应用部署到服务器，基本流程是什么？

查看参考答案
传统方式：装运行环境（Node/Python/Java）→ 传代码（git pull / scp）→ 装依赖 → 起服务（pm2 / systemd 守护进程）→ Nginx 反向代理（80/443 → 应用端口，顺便做 HTTPS、静态资源、负载均衡）→ 防火墙放行端口。
现代方式：写 Dockerfile → 构建镜像 → docker run / compose up → Nginx 反代到容器端口。
加分项——提到 CI/CD（push 代码自动构建部署）、HTTPS 证书（Let's Encrypt）、域名 DNS 解析。

C1 · 判断力

老板说"我们要把客服全部换成 AI Agent"。你会怎么回应？

查看考察点
不直接答"好"或"不好"。好答案：先问目标（降本还是体验？）、拆解哪些环节适合 Agent 哪些适合 Workflow、提到人工兜底和灰度上线。

C2 · 成本意识

一个 Agent 任务的 Token 消耗是 Workflow 的 4-8 倍。公司每天有 10 万次客服对话，你会怎么设计架构控制成本？

查看考察点
模型路由（简单问题给小模型）、能用 Workflow 的环节不用 Agent、缓存常见问答。

C3 · 排障思维

线上 Agent 突然开始答非所问，你按什么顺序排查？

查看考察点
结构化排查：先看输入是否变了 → 看工具返回是否异常 → 看上下文是否被污染 → 看模型/版本是否变更。

C4 · 设计思维

如果让你从零设计一个"帮 HR 筛简历的 Agent"，你会怎么设计？

查看考察点
四模块意识（LLM、工具、记忆、规划）、Human in the Loop（最终决策留给人）、安全边界（不能泄露候选人隐私）。

C5 · 开放发散

你觉得未来两年，Agent 最先在哪个岗位真正替代人？为什么？

查看考察点
无标准答案。看有没有自己的观察和判断逻辑，看论证质量。

D1 · 评审题

给候选人看一张 AI 生成的海报/网页（提前准备，故意留几处瑕疵：配色脏、层级乱、文案 AI 味重）。问："这个能直接用吗？如果不行，你会怎么改？"

考察：能不能指出具体问题（配色、对比度、信息层级、留白、文案腔调），而不是只会说"感觉不好看"。

D2 · 选择题

展示同一内容的两个排版方案（一个花哨一个克制），问选哪个、为什么。

考察：审美是否有"场景意识"——给老板汇报和给 C 端用户的标准不一样。

D3 · 文案改写

给候选人一段"AI 味"很重的文案（如"在快节奏的现代社会中，我们迎来了激动人心的时刻……"），请他改成能直接发的版本。

考察：能不能识别"AI 味"（空洞形容词、排比堆砌、无信息量开头）并改出有人味的文案——这是天天用 AI 的人才会有的手感。

D4 · 品味溯源

"你关注的设计/产品类账号、网站、newsletter 有哪些？最近看到哪个设计觉得做得好？"

考察：审美是输入决定的。零输入的人大概率没有真审美。

追问话术（快问快答环节最能验真伪）

  • 候选人背出概念后追问："你在什么场景里真的用到过这个？"——背八股的会卡壳
  • "这个方案有什么缺点？"——只会背优点的是看文章的，能讲缺点的是动手过的
  • "如果让你给同事讲明白这个概念，你会怎么打比方？"——考真理解，能自己造类比的才算懂
  • 审美题追问："你说这个配色不好，具体哪里不好？换成什么？"——要落到具体值，不接受"感觉"

✅ 加分信号

  • 有自己的 Prompt 库 / Skill 库 / 工作流模板
  • 能说出至少一个 AI 工具的"坑"和规避方法
  • 答概念题时能带出自己的使用场景，而不是只背定义

❌ 减分信号

  • 把 Agent 当搜索引擎用（一问一答式）
  • 从不校验 AI 输出
  • 说不出任何一个具体工具的优缺点
